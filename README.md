# Serifu Motion

セリフ音声から、アバターの表情・頭・胴体の動き（emo）を自動生成するWebアプリです。表情は感情ラベルやBlendShape名ではなく、FACS の Action Unit（AU）で記述します。

- **スタジオ**: 話者ごとの音声、または会話音声（自動で話者分離）を読み込むと、emo を生成して3Dアバターに適用します。話者別トラックのタイムラインで、フレーズごとの感情の差し替え、キー編集、うなずき等の挿入ができます。emo JSON / AU CSV / 動画で書き出せます。
- **ライブ**: iPhone などのカメラとマイクで、リアルタイムにアバターを動かします。カメラから拾うのは瞬きと口の形だけで、表情・頭・胴体はマイク音声からリアルタイムに生成します。
- 読み取りの入力は声の調子（高さ・大きさ・間・声色）で、言葉の意味は使いません。ただし現状の読み取りは英語の学習データと同じ条件でしか働かず、日本語の音声では働きません（下の「自己評価の現状」）。UIは日本語・英語・中文・한국어・Español・Français・Deutsch。

## 動きの作り方（アニメ解釈レイヤー）

俳優の表情をそのまま写すのではなく、セリフを「読んで、演出して、演じる」3段で動きを作ります。

1. **読み取り**: 学習したネットワークが、音声からフレーズごとの感情（平静・喜び・悲しみ・怒り・恐れ・嫌悪）と強調の位置を読みます。後から生成する場合は3モデルの合議、ライブは先読みをほぼしない2モデルの合議です。合議には、セリフそのものから読むモデルと、同じ録音のほかのセリフと比べて読むモデルがあり、録音が短いときは前者だけで読みます。
2. **演出**: フレーズごとに、予備動作、セリフの前に決めるキーポーズ、強調へのアクセント、抜き、視線、まばたきを時刻つきで決めます（演技プラン）。タイムラインに表示され、感情をクリックで差し替えると即座に演出し直します。
3. **演技**: ばねの動き、加算のジェスチャ、感情で形が変わる口の動きで、リグ空間の40チャンネル（AU 20、視線2、頭4、胴体4、演技用10）を出力します。

演技の法則は、アニメーションの原則をもとに規則として書いたものです。アニメ作品から学習したものではありません。「演技スタイル」で、音声から生成した動きをそのまま適用する従来の方式（リニア）にも切り替えられます。

## 構成

| パス | 内容 |
|---|---|
| `app/` | Webアプリ本体（ビルド不要、静的ファイル）。GitHub Pages で公開 |
| `app/core/features.js` | 音声特徴抽出（学習時もこのファイルをNodeで使い、ブラウザと完全に同じ特徴にする） |
| `app/core/model.js` | 時間畳み込みネット（TCN）の推論。オフライン版と、低遅延の因果版（ストリーミング） |
| `app/core/animate.js` | アニメ解釈レイヤー（演出と演技）。オフライン用とライブ用 |
| `app/core/generator.js` | 読み取りと演出をつなぐ生成器 |
| `app/avatar/` | オリジナルの3Dアニメ調キャラクター4体、AUで直接動く表情リグ、キャラクター別の演技設定 |
| `train/` | 学習と自己評価（映像からの数値抽出、学習、`evaluate2.py` ほか） |
| `tools/` | 比較動画の生成ほか |
| `models/anim_stats.json` | 公開アニメ映画の頭の動きの統計（数値のみ） |

## セリフの意味を読む仕組み

読み込んだ音声は、ブラウザの中で文字に起こします（`app/core/asr.js`、`asr_worker.js`）。その文章を、設定画面で入れた Claude API のキーで外部のAIに送り、フレーズごとの感情と強さを受け取って演技トラックの印にします（`app/core/understand.js`）。キーはブラウザの中だけに保存され、送るのは文章だけで、音声は送りません。キーが無いときは端末内の簡易な読み取り（単語の一覧による判定）を使います。

同梱している第三者の部品:

- 音声認識モデル Whisper base（OpenAI、MIT License）。[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache License 2.0）が公開している ONNX 版を `app/models/whisper/` に置いています（GitHub の1ファイル100MBの上限のため、デコーダーは2つに分割）。
- 話者の聞き分けに使う声紋モデル CAM++（[3D-Speaker](https://github.com/modelscope/3D-Speaker)、ModelScope `iic/speech_campplus_sv_en_voxceleb_16k`、Apache License 2.0）。sherpa-onnx が公開している ONNX 版を `app/models/speaker/` に置いています。
- [ONNX Runtime Web](https://github.com/microsoft/onnxruntime)（Microsoft、MIT License）: `app/vendor/ort/`。

## 学習データ

- [CREMA-D](https://github.com/CheyneyComputerScience/CREMA-D)（Open Database License）: 俳優91人が12文を6感情で話した映像7,442本。映像そのものは保持・再配布せず、MediaPipe で抽出した数値（AU強度、頭部姿勢、肩の動き）と音声特徴だけを学習に使います。
- Blender の公開映画5本から、頭の動きの統計（数値のみ）を取り、動かす量の調整と比較に使っています。

## 自己評価の現状（2026年11月14日）

**感情の読み取りは、学習データと同じ条件（英語の決まった12文、同じ録音環境）でしか働いていません。日本語の音声では働きません。** この節の前半の数字は、その条件の中で測ったものです。

事前に決めた8項目の基準は、学習に使っていない俳優のセリフですべて満たしていますが、強い合格ではありません。俳優1人ずつに分けると、8項目すべてを満たすのは9人中2人です。

感情の読み取り（6択、偶然は17%）は、5回目の改善で短い録音とライブを作り直しました。事前に決めた4つの目標を、それまで評価に一度も使っていない話者9人で1回だけ測り、すべて満たしています。ただし、同じモデルを以前の評価用の話者9人（難しい話者が多い）で測ると、2項目が55%にわずかに届きません。

| 録音の条件 | 目標 | 新しい話者9人 | 以前の評価用9人（改善前 → 改善後） |
|---|---|---|---|
| セリフ1本だけ | 55%以上 | 67.3% | 43.1% → 58.0% |
| 同じ感情ばかり約13本 | 55%以上 | 63.1% | 40.8% → 53.8% |
| 1人の82本をまとめた長い録音 | 64%以上 | 73.1% | 66.0% → 65.6% |
| ライブ、セリフの終わりで演じている感情 | 55%以上 | 63.1% | 47.8% → 53.4% |

- 話者による差が大きく、4つの目標をすべて1人で満たすのは、新しい話者9人中7人、以前の評価用9人中3人です。
- ライブは、話し始めから0.5秒では38%、1秒では53%です（新しい話者）。話し始めの時点では、まだ外すことのほうが多いです。
- 感情が正しく与えられた場合、表情から意図した感情を読み取れる割合は93〜94%です（実写の顔で学習した判定器による）。
- 長い会話と、iPhone 実機でのカメラとマイクは未確認です。
- 演技として良いかどうかは数値では測れていません。
- 話者の分け方と目標を決めた時点は `train/SPLITS.md`、結果の生データは `train/results/` にあります。

### 学習データの外で確かめた結果（2026年11月14日）

| 確かめたこと | 結果 |
|---|---|
| 日本語の音声。声優3人が平静・喜び・怒りで読んだ900本。目安（55、55、64、55%）は測る前に固定 | セリフ1本だけ12.2%、同じ感情ばかり25本11.6%、75本の長い録音15.6%、ライブ17.3%。すべて目安に届かず、偶然（16.7%）と同じ。平静と喜びはほぼ1本も当たらず、ほとんどを怒りか恐れと読む |
| 英語で、学習に使っていない文。12文のうち3文を抜いて学習し直し、その3文を読ませる（調整用の話者7人） | セリフ1本だけ 66.2% → 49.0%、長い録音 66.4% → 54.5%。平静と喜びが大きく下がる |
| 英語で、セリフの間の雑音を消した録音（調整用の話者7人） | セリフ1本だけ 68.8% → 36.6%、長い録音 73.6% → 53.4%。平静と悲しみを、怒りや喜びと読む |

- 原因は、学習データが1種類（英語の12文、同じ録音環境）だけだったことです。ネットワークは声の調子だけでなく、文ごとの言い回しの型と、声と部屋の雑音の差も手がかりにしていました。上の表の目標達成は、学習と同じ12文で測ったぶん甘い数字です。
- ライブはブラウザの雑音抑制を通した音を使うので、実機では雑音の影響を受ける可能性があります（実機では未測定）。
- 次の改善では、文・録音環境・言語の種類が多いデータで学習し直し、学習に使っていないデータで確かめます。
- 日本語の確認に使った音声（声優統計コーパス）は分析目的でのみ利用でき、このリポジトリにもアプリにも含めていません。
